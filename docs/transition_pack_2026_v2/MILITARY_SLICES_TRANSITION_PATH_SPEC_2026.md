# Military SLICES — Cross-Service Transition Path Specification (2026)

## Purpose

This is not a universal military-transition checklist for the UI.

It is the **defined path** that bounds HELM's search and action space.

### Active execution invariant

Every run must know two different anchors:

1. **Human anchor** — the outcome the member is actually trying to achieve now (for example: “leave with a civilian job lined up,” “choose an education path,” or “make this resume submission-ready”).
2. **Next path target state** — the next bounded milestone on the service-aware transition path.
3. **Current timeline window** — where the member is relative to separation/retirement.
4. **Eligible task horizon** — which 1–3 tasks can materially move both the human anchor and the next path state forward now?
5. **Blocking gate** — what prevents the next task from being completed?
6. **Authority** — can the system close it, or must a human/service authority act?

**Do not confuse a program milestone with the human objective.** Completing TAP, Capstone, or a checklist item can be necessary without becoming the user’s goal.

If the human anchor is not yet known, the only active objective is to establish the smallest useful anchor. Do not activate the broader transition universe while the objective is undefined.

No task is activated solely because it is generally relevant to military transition.

# Canonical path

The time windows below normalize the common patterns found across current DoD/service sources. Service overlays may rename or shift individual tasks.

## Window 0 — Determine path identity only when needed

Potential discriminators:

- service;
- component/status;
- separation vs retirement;
- known transition date or date range;
- current timeline window;
- declared post-service target if one exists.

Do not force collection of all fields up front. Acquire only those needed to select the next task.

### Target state

`PATH_IDENTIFIED`

---

## Window A — 24 to 18 months before transition

### Intent

Establish the transition path early enough to exploit time-sensitive opportunities.

### Candidate tasks

- begin service transition program if eligible/recommended;
- establish/confirm transition date or working date range;
- conduct initial self-assessment/counseling where service supports early start;
- establish broad post-service direction: employment, education, technical training, entrepreneurship, continued service, undecided;
- identify family/location constraints only if they materially shape the path;
- for retirees, begin service retirement-planning process/resources.

### Do not automatically activate

- detailed benefits shopping;
- job recommendations;
- resume rewriting;
- relocation planning;
- medical/claim details;
- every retirement administrative item.

Activate them only if the current target/path requires them.

### Target state

`TRANSITION_PATH_ORIENTED`

---

## Window B — 18 to 12 months / no later than 365 days

### Intent

Close mandatory transition-program initiation gates and define an actionable post-service route.

### Common tasks

- self-assessment / Initial Counseling or IIC;
- Pre-Separation Counseling;
- start/update ITP;
- determine required tier/track or equivalent;
- establish transition target and major constraints;
- identify career/education/vocational/entrepreneurial direction enough to choose relevant curriculum/tracks;
- for service retirement processes, submit or stage retirement actions according to service rules.

### Common hard gate

For covered members, current DoD/service implementation generally requires TAP initiation no later than 365 days before transition.

### Target state

`MANDATORY_TRANSITION_PATH_ACTIVE`

---

## Window C — 12 to 9 months

### Intent

Turn orientation into preparation.

### Candidate tasks

- complete service/core transition curriculum;
- complete occupation/career crosswalk or skills translation work;
- build financial transition baseline;
- identify civilian career/education evidence gaps;
- begin master resume/evidence inventory when employment is on path;
- identify certifications/licensure only if relevant to target path;
- research SkillBridge/CSP/experiential options if materially relevant;
- begin records/document preservation if access loss is foreseeable.

### Promotion constraint

A resume upload during this window does **not** authorize job recommendations unless career exploration/job search is on the active path.

### Target state

`PREPARATION_BASELINE_READY`

---

## Window D — 9 to 6 months

### Intent

Close prerequisite and readiness gates for the selected route.

### Candidate tasks

- complete DOL/VA/core/track requirements that remain open;
- finalize education/training target if education path is active;
- finalize employment evidence/resume foundation if employment path is active;
- complete SkillBridge/CSP application/approval work if active and allowed;
- identify relocation decision window only if location materially affects target;
- begin current-source benefit/medical/claim timing checks when they enter the active path;
- build an evidence-backed post-transition financial plan.

### Target state

`ROUTE_PREREQUISITES_CLOSED`

---

## Window E — 180 to 90 days

### Intent

Execute time-sensitive pre-separation actions.

### Candidate tasks

- Benefits Delivery at Discharge gate when relevant: current VA window is 180–90 days before separation;
- service separation/retirement physical and records actions according to current service/medical policy;
- final-180-day experiential program execution if approved;
- begin serious job applications when employment path and availability support it;
- finalize move planning if relocation is active;
- close Career Readiness Standards needed for Capstone;
- review key administrative records that could affect separation documents.

### Hard common deadline

Capstone must be completed no later than 90 days prior in current common/service TAP implementations.

### Target state

`CAPSTONE_READY`

---

## Window F — 90 to 30 days

### Intent

Verify readiness and close final administrative/transition execution gates.

### Candidate tasks

- complete Capstone / Commander's Verification as service requires;
- verify ITP/CRS deliverables;
- finalize job/education start plan;
- ensure personal access to records/accounts after CAC/service credential loss;
- review separation document data/draft where service process permits;
- finalize household goods/relocation execution if active;
- finalize leave/terminal leave/PTDY-related service admin if applicable;
- verify healthcare/life-insurance enrollment decision windows only when relevant.

### Target state

`FINAL_OUT_READY`

---

## Window G — Final 30 days / final out

### Intent

Execute, verify, preserve.

### Candidate tasks

- final out-processing;
- preserve records and account access;
- verify DD Form 214 / service separation record where available;
- complete ID/CAC/retiree credential actions as applicable;
- verify pay/account contact information;
- confirm move/transportation execution if active;
- confirm first post-service job/school/training start if on path.

### Target state

`SEPARATION_EXECUTED`

---

## Window H — Day of transition through first 365 days

### Intent

Stabilize the transition and close post-service gates that could not exist before separation.

### Candidate tasks

- activate/verify healthcare and benefits when applicable;
- follow up on VA claim/benefit processes when active;
- stabilize employment/education/relocation path;
- correct separation records if errors are discovered;
- close remaining household/pay/admin issues;
- reassess career plan only when the user declares a new target or the current plan materially fails.

### Target state

`POST_SERVICE_STABLE`

# Service overlays

## Army overlay

### Terms

- Soldier
- ETS / REFRAD / retirement date
- Army TAP
- Individualized Initial Counseling (IIC)
- Army Day
- MOS Crosswalk
- Transition Center / TAP Center
- Retirement Services Officer (RSO)
- Army Career Skills Program (CSP)
- IPPS-A

### Current timing signal

Current Army sources say:

- normal separation: TAP can begin about 18 months prior;
- retirement: TAP can begin about 24 months prior;
- required initiation: no later than 365 days prior;
- Capstone: no later than 90 days prior.

### 2026-specific update

Army CSP and SkillBridge participation requests were moved into IPPS-A in May 2026 under current Army guidance.

## Space Force overlay

### Terms

- Guardian
- DAF TAP

### Rule

Use the DAF transition path unless a current USSF source establishes a service-specific exception. M&FRC resources explicitly serve Guardians.

## Coast Guard overlay

### Terms

- Coast Guard member / Coast Guardsman
- Transition Assistance Program (TAP)
- Transition/Relocation Manager (TRM)
- Health, Safety and Work-Life Regional Practice (HSWL RP)
- SPO / Command
- DHS Transition Day
- Sea Legs / Departing the Service Checklist

### Current timing signal

Current Coast Guard TAP page says eligible members begin 365 days prior and complete self-assessment, individual initial counseling, pre-separation counseling, and core curriculum; CAPSTONE no later than 90 days prior. Current PPC Separations guidance also states members may begin transition one year out from separation or two years out from retirement. Treat the two-year retirement window as an early-start opportunity, not as a change to the 365-day mandatory gate.

### Conflict handling

Older Coast Guard toolkit material still contains legacy ~180-day language. Treat this as a provenance/freshness conflict. Prefer current TAP page plus current governing law/policy for the executable gate.

# HELM task activation rule

For every candidate task:

```text
IF task is on current time/service path
AND task materially advances/validates/blocks/threatens declared target
THEN task may become active
ELSE keep latent
```

At most:

- **1 primary gate**;
- **1–3 active tasks**;
- **3 supporting state changes** visible at once.

The rest stays in governed state or latent evidence.

# Escape rule

HELM may leave the current checklist/task window only when grounded evidence establishes an external dependency that materially:

- blocks the active task;
- invalidates the active task;
- changes the timing of the active task;
- changes the authority required;
- threatens the declared target state.

The escape must be provenance-tagged and explain why the boundary was crossed.

# Evidence freshness rule

Every task should be separated into:

- durable task concept;
- service-specific current process;
- volatile implementation facts.

Example:

```text
durable task: preserve access to records after leaving service
service process: use current service personnel/medical systems
volatile fact: exact portal URL/login workflow in 2026
```

BHE should not hard-code volatile facts when a current source can be queried at execution time.

# Volatile service-program rule

Some service programs change faster than the durable path. Do not hard-code their current implementation details into the durable task scaffold.

Example: DAF changed Air Force and Space Force SkillBridge maximum participation and approval authority effective 31 March 2026, with rank-dependent limits. If SkillBridge becomes an active task, fetch the current DAF policy and bind the result to the current execution. If SkillBridge is latent, do not spend tokens refreshing it.
